# 第三阶段 3A / 3B（柜门拉手）验收记录

## 3A：同一 Canvas 会话稳定性

测试保持同一个 3D Canvas，不退出 3D、不销毁 renderer，连续 50 轮执行：1F/2F 往返、相机拖拽、缩放、画布点击选择/取消选择。

修复前的对照结果（旧 floor key + 192 条材质缓存）：Canvas DOM 数量仍为 1，但一次 50 轮会话累计 PBR 材质创建 22,881 次、材质淘汰 17,952 次、PMREM 生成 60 次；这说明 DOM 数量稳定并不代表 renderer 和资源工作集稳定。

修复后结果：

| 指标 | 50 轮开始 | 50 轮结束 |
| --- | ---: | ---: |
| Canvas 数量 | 1 | 1 |
| PBR 材质创建 | 589 | 589 |
| PBR cache miss | 589 | 589 |
| 材质淘汰 | 0 | 0 |
| PBR 贴图生成 | 26 | 26 |
| PMREM 生成 | 61 | 61 |
| shader program | 17 | 17 |
| 贴图缓存条目 | 26（活动 13） | 26（活动 13） |
| 材质缓存条目 | 589（上限 768） | 589（上限 768） |
| WebGL 可见纹理 | 70 | 70 |
| WebGL 可见网格 | 1,728 | 1,728 |

JS 堆在浏览器调度下由约 304 MB 波动到约 488 MB，但 GPU 资源计数、PBR/PMREM 生成和淘汰均不再随轮次上升；因此这组 JS 堆变化不判定为资源泄漏。材质缓存上限 768 来自本次 1F+2F 会话实测的 589 个唯一 PBR key，而不是按 1,370 个运行时材质盲目扩容。

## 3A：语义标签

候选构件增加了类别、所属家具、楼层/房间、可选择父对象 ID、几何签名和 canonical 材质 key。标签只写入 `userData`，不参与尺寸或视觉计算。

## 3B：第一批柜门拉手

本批仅实例化完全相同、静态闭合、非透明的 edge-pull 柜门拉手。1F 固定机位实际发现 19 个拉手、4 个父家具、4 个几何签名；所有实例共享同一个 canonical 材质 key，`instanceId` 映射回父家具。

| 指标 | 实例化前 | 实例化后 | 变化 |
| --- | ---: | ---: | ---: |
| 可见网格 | 1,524 | 1,509 | -15 |
| 绘制调用 | 1,430 | 1,415 | -15 |
| 三角形 | 341,205 | 341,205 | 0 |
| 材质 | 1,019 | 1,016 | -3 |
| 几何 | 1,403 | 1,388 | -15 |
| 贴图 | 29 | 29 | 0 |
| 阴影灯 | 0 | 0 | 0 |

同一固定机位、同一楼层和同一窗口截图的全页差异为 113 / 921,600 像素（0.0123%），平均通道绝对差 0.00019；差异仅为浏览器截图/抗锯齿微小波动，模型轮廓、家具细节、颜色与材质通道未发生变化。实例化没有减少三角形，也没有降低圆角段数。

已验证：对象列表选择水吧台后当前对象仍为父家具 `W-1F-011 南段水吧台`；实例语义统计为 19 个实例映射到 4 个父对象。楼层切换和相机连续操作保持 Canvas/renderer 资源稳定。
