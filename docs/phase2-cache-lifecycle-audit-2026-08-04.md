# 第二阶段：缓存与资源生命周期（2026-08-04）

## 范围

本阶段只修改 PBR 贴图/材质缓存、PMREM 环境资源生命周期和统计依赖。没有修改几何、家具位置、户型、灯光数量、DPR、裁剪、合批、实例化或烘焙。

## 实施内容

- PBR 贴图继续按材质族/资源类型共享，UV 重复和旋转不再生成新的 canonical 贴图。
- 贴图和材质缓存都维护引用计数；只淘汰 `refs === 0` 的空闲条目，卸载时释放 GPU 资源。
- PBR 贴图生成、材质创建、缓存命中和淘汰现在有独立计数，便于区分“缓存命中”与“实际生成”。
- `PbrMaterial` 的 UV 依赖改为 primitive 值，避免每次 React 重渲染因新数组引用重新创建材质。
- PMREM 环境贴图改为按 WebGL renderer 共享；引用归零后延迟 1.5 秒释放，避免模式切换时重复生成或释放仍在使用的环境纹理。
- 保留现有编辑模式阴影配置。本阶段没有把“暂停阴影更新”计入性能收益。

环境：同一桌面内置浏览器、1F、默认鸟瞰机位、同一拖拽路径。每轮重新加载页面后再进入 3D；拖拽阶段记录 `interactionActive=true` 的窗口。

| 正在拖拽 | 10.22（9.95–11.65） | 4.95（4.56–9.82） | 5.47（5.10–10.58） |

内置浏览器处于后台时 rAF 调度波动很大，因此 FPS 没有宣称提升；与第一阶段 20.59 / 11.73 的单次基线相比，本阶段可确认的是资源生命周期和生成次数稳定，而不是 FPS 改善。后续若要优化帧率，应在独立前台窗口中重新测量，不能把后台调度差异当作收益。

需要继续关注：相机操作会让非 PBR 的延迟资源从 41 张可见贴图增至 43 张，材质/几何计数也会在不同页面加载时波动。这部分不是本阶段通过几何替换解决的，后续应单独定位其创建源。

## 灯光与阴影说明

编辑模式实测始终为 7 盏实时灯、0 盏阴影灯。原因是编辑配置明确关闭主场景实时阴影投射，仅保留环境/半球和有限的功能灯；因此“拖拽时暂停阴影更新”在本阶段没有可测收益，也没有计入 FPS 改善。
