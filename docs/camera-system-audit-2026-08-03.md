# 全屋相机系统审计与自动构图改进报告

日期：2026-08-03
范围：仅相机、视图、墙体剖切显示、相机界面与相机持久化；未修改墙体、房间、门窗、楼梯、家具、柜体、灯具、点位、材质或真实方案数据。

## 结论摘要

仓库原有相机能力并非缺失，而是分散在楼层视图、房间导览、探索模式、灯光场景和渲染相机保存中。主要冲突是：总览和对象聚焦仍有固定坐标、房间导览与 `cameraViews` 可能表达同一视角、临时渲染相机和 workspace 相机的保存边界不清晰，以及切换焦点后目标点/剖切状态可能残留。

本轮新增统一的纯函数取景层 `lib/camera-composition.ts`、微调层 `lib/camera-adjustment.ts` 和版本化渲染相机存储层 `lib/render-camera-storage.ts`，并把既有入口接到这些模块。动态候选会在房间边界、门口、墙角、可站立区域和家具碰撞约束内评分；找不到合格候选时按“房间推荐斜视 → 门口 → 角落 → 安全斜俯视 → 楼层俯视”回退，不回退到穿墙或无限远镜头。

## 三、统一自动构图算法

候选输入：目标包围盒、房间/楼层边界、主要轴向、门口和墙角、可站立区域、墙体/楼板/大型家具碰撞、视线遮挡、实际可见画布、桌面/手机宽高比、面板内缩、视图类型、构图边距和安全距离。

候选评分依次考虑：目标完整可见、目标占比、视线遮挡数、距墙安全距离、是否进入柜体/家具、纵深可见性、FOV自然度、用途高度、需要隐藏的墙体数量和房间类型适配度。目标覆盖率以相机投影视锥估计，并对斜向视图使用平面包围盒对角线和纵深贡献留出额外安全余量。

回退顺序：房间推荐斜视 → 门口视角 → 房间角落 → 安全斜俯视 → 当前楼层俯视。候选全部不合格时不穿墙、不贴墙、不使用极远镜头。

## 四、微调与界面

桌面端新增紧凑相机控制区：当前焦点、当前模式、左转、右转、上/下观察、拉近、拉远、适配、重置、返回进入前视角、保存视角、更多视角。相机设置中提供 FOV、相机高度、过渡速度、构图边距、墙体剖切、顶面显示和相机碰撞。

手机端保留房间选择、推荐视角、左右旋转、双指缩放和重置；微调只改变显示状态，不提升编辑权限。旋转围绕稳定目标点，缩放被最小/最大距离与碰撞约束限制，普通微调不进入户型撤销重做。

## 五、保存体系

* workspace `cameraViews`、`roomTourViews`：继续保存专业视角和导览视角，旧字段兼容。
* `localStorage` render cameras：v2 记录楼层、房间/对象、position、target、FOV、相机高度、墙体模式、顶面状态、灯光场景、绘图预设和编辑/展示模式；只有明确点击“保存视角”、生成或删除时写入。
* 当前会话：React 状态保存临时微调、焦点历史、剖切覆盖和待恢复视角，不自动持久化。
* 恢复前：校验楼层、房间和对象是否存在；跨楼层恢复先切换上下文再应用 pose；旧 v1 只在内存迁移，不自动写入默认方案。

## 七、未稳定或需确认的项目

1. 极窄卫生间、长走廊、楼梯转折：如果主要家具或门洞遮挡视线，会回退到安全斜俯视；是否接受该展示角度需要确认。
