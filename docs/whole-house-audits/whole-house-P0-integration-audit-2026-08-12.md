## A-G 集成结论

### A｜版本真值

当前最严重的不是某一个房间的风格，而是集成边界：主工作树和执行树都在 `HEAD 1892fcb` 上但各自有未提交数据；YARD 甚至新增了主树没有的路由和组件；GitHub Pages 仍是旧发布。主任务必须把迁移脚本作为消费入口，把执行报告作为证据而不是直接复制 `default-workspace.json`。

### B｜灯光

- 五个 canonical key 已在共享合同和 B2/1F/2F 主数据中出现，但 B1/YARD 执行数据没有完整落地。
- 旧兼容场景仍存在于底层集合，不能被“按钮只显示五个”视为清理完成。
- B2 物理点位重复/错误标高；B1 一盏灯具家族错误；1F 餐桌吊灯依附尚未随桌心同步；2F 灯/柜 `needsLighting` 与 `relatedFurnitureId` 不完整；YARD 21 灯组与户外柜、电源/排水依附只在 overlay。
- 实时灯光是否按楼层受光面、exposure、ambientFill 和五场景实际工作，除 UI 过滤外尚无全屋 runtime 证据。

### C｜柜体

执行树已分别推进 B2 4、B1 4、1F 6、2F 8 个 `cabinetInterior` 对象，但主数据还未统一消费。B2 圆弧酒柜、2F 柜高/host、B1 洗衣柜、1F 水吧/冰箱、YARD 三件户外柜仍各有施工与复尺条件。重点柜体不能以闭门外壳、写实图或静态代表卡代替内部、开合、材质五金、灯带电源、水路、散热、检修和收口验收。

### D｜跨专业依附

目前多个依附关系是“字段声明”而非闭环：B2 水吧/影音/大板桌、B1 洗衣房、1F 水吧/客卫/餐桌吊灯、2F 主卫/衣帽间/阳台柜、YARD 户外厨房/洗衣柜。必须把柜体—灯光—插座—给排水—吊顶—家具多状态作为同一验收图或对象关系表。

### E｜功能 P0

主要通道、门扇、楼梯、床尾/柜前、桌椅拉出、柜门开启、厨卫排水防水、地下防潮通风、院子排水安全均有未闭合项。除明确交叠外，B2 柱、B2 门、2F 主卫边界、2F 柜高、B1 天窗、1F 淋浴窗、YARD 标高都必须标 `estimated/需复尺`；不能用当前坐标下的 900/650/2750 等数值作毫米级施工承诺。

### F｜模型与渲染

B1/2F 预检硬阻断，B2/1F/2F 报告还指出 actual 3D 与写实图/历史归档不同步。写实图存在用构图隐藏水吧/桌椅、冰箱通道、主卫重叠、阳台封闭性、楼梯墙端和柜体内部缺项的风险。正式交付必须以同 revision actual 3D 为硬参考。

### G｜性能与发布

柜体内部节点、灯具和实时灯光加入后，现有报告没有新的 runtime FPS/draw calls/帧耗时证据；关闭态门控是代码意图，不是全屋性能验收。主发布入口未包含院子，GitHub Pages 也未包含最新 YARD/柜体/灯光成果。移动端和桌面端的灯光面板、相机/分析面板遮挡需在 clean build 后按至少一个桌面和一个窄屏尺寸复审。
