# 交互流畅度与左侧导航回归审计（2026-08-03）

> 历史说明：本文早期版本包含“相机拖拽代理场景”的对比数据。该口径已被第一阶段移除代理方案取代，704 三角形 / 66 材质等拖拽数据无效。请以 [第一阶段完整模型基线](phase1-full-scene-baseline-2026-08-04.md) 为准。

## 结论

- 桌面左侧栏恢复为默认展开的 192px 文字导航；父级网格同步在 192px / 56px 之间切换，并使用本地偏好记住上次状态。
- 编辑档的 PBR 贴图改为材质族级复用；UV 重复和旋转留在材质参数，不再进入贴图缓存键。
- 编辑档只启用 baseColor，DPR 为 1–1.5，关闭抗锯齿、保留缓冲、全场景实时阴影和高成本物理玻璃；精致展示保留完整 PBR 与高质量阴影。
- 相机拖拽期间切换到预挂载的交互代理层，松手 320ms 后恢复完整原始场景。代理层只改变实时绘制集合，不修改户型、对象数据、尺寸、位置或精致展示造型。
- PBR 贴图缓存硬上限 32 组，材质缓存硬上限 192 个；淘汰与临时实例卸载时调用 dispose。

### 完整造型静止态

松手后恢复完整场景，实测 1,636 个可见网格、1,181 个可见材质、7 盏实时灯、0 盏阴影灯。静止态继续保留全部原造型；编辑档的核心指标是输入期间的 66 次绘制调用。

### 精致展示档

最终实测：109 张贴图、1,325 个可见材质、45 盏实时灯、1 盏阴影灯、32 组贴图缓存、192 个材质缓存、约 595.9 MiB JS 堆，DPR 1.25。后台自动化窗口下平均 2.87 FPS、最低 1.30 FPS；该档明确用于最终样板间效果，不作为交互编辑档。

## 卡顿前三项来源

1. 贴图缓存键包含每个表面的重复比例和旋转，导致同一材质按墙面、地面和家具尺寸重复生成整套贴图；缓存无上限且没有可靠释放。
2. 家具元数据把 presentation 质量直接传进材质组件，绕过编辑档质量策略；baseColor、normal、roughness、AO、height 同时启用，并创建大量高成本玻璃物理材质。
3. 编辑时仍渲染完整高细节场景、实时阴影和多盏灯，初始 DPR/抗锯齿/保留缓冲偏高；隐藏细节没有形成专门的相机交互绘制集合。
