# 第一阶段：完整模型基线（2026-08-04）

## 阶段范围

本阶段只移除了相机操作期间的轻量代理场景，并修正了导航渲染回归脚本。没有做合批、实例化、门户/遮挡裁剪或光照烘焙。编辑与相机操作始终挂载同一套完整模型；`cameraInteractionActive` 仅用于性能采样，不再控制场景可见性。

此前审计中“拖拽时 704 个三角形 / 66 个材质”的数据来自代理场景，已标记为无效，不能与完整场景作性能对比。

## 公平口径

- 同一设备、同一 Chromium 内置浏览器、同一 1F 总平面、同一 1280×720 视口。
- 固定初始机位，完整模型加载并稳定采样后记录；拖拽窗口与松手静止窗口分别记录。
- 不要求相机移动前后可见对象集合一致；验证的是完整场景资源规模、几何精度、家具签名和主要材质通道没有切换为代理/低模。

## 连续操作内存观察

连续三次旋转、平移和缩放后，缓存条目保持 27 个贴图 / 192 个材质，估算贴图缓存保持约 20.50 MiB；JS 堆在等待稳定后约 251.1 MiB。运行期间 `gl.info` 的几何体从 1,527 增长到 1,648、材质从 1,202 增长到 1,260，这提示仍有动态资源延迟创建或释放时机需要在第二阶段继续审计，不能在本阶段宣称无内存增长。
